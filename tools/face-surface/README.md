# Regenerating the face surface

From the repository root, run:

```sh
python3 tools/face-surface/generate.py
python3 tools/face-surface/generate.py --check
```

You need Python 3 (standard library only), Git, and rustc. The generator compiles
`tools/face-surface/render.rs` into a temporary directory beneath `target/`, runs
it once, then removes that temporary directory. That entrypoint includes the
production `src/bands/shell/test.rs` unchanged and calls
`render_component_showcase()`. The enclosing Test pane calls the same function
from `render_test_showcase()`. You start no HTTP server, browser, or JavaScript
runtime when generating these files. Cargo, tests, and CI are separate journeys.

## Frozen byte boundaries

You read the primitive names from the ux index's `library/_<name>.css` children,
then sort them. You read and sort the variable names from `author-face.json`
without adding `--` or copying their CSS values. The root ux index's additive
`artifacts` list seats the surface and showcase index alongside the existing CSS
`children`; the CSS concatenation list and runtime remain unchanged.

Each HTML file concatenates all outermost matching primitive elements in its
own showcase category, in renderer order, without separators, a trailing
newline, attribute reordering, entity decoding, or HTML reserialization. The
selector table lives in `generate.py`; it selects markup, never supplies it.
Wrappers belonging to the primitive (input/select labels, tab groups, table
container, modal overlay) stay with their contents. Showcase headings and domain
pack simulations stay outside. The calendar and IP calendar retain their
server-rendered empty hydration slots, not a browser-populated day/address grid.

The production portal-remove simulator currently contains an extra closing div.
The range reader records unmatched closings outside primitive ranges and leaves
those bytes alone. A missing close or unmatched close inside a selected primitive
stops generation. You do not use this generator to repair production markup.

For toast only, `toast.py` statically lowers the construction statements in
`showCoronatioToast`, at `src/bands/shell/document-4-tail.rs:14-26` on the initial
source. It reads creation tags, class assignments, dataset and explicit
attributes, text expressions, and append order from that source. Message and
variant inputs come from the showcase's existing toast controls in source order;
the controls themselves are not frozen. The result ends before timer state is
added. You see `origin: browser-constructed` and the derived `constructor` locator
on this entry; absent origin on the other entries means server-rendered. New
unsupported constructor syntax stops with its exact statement rather than
silently retaining old markup. This is static construction, not browser capture
or a claim about a browser's HTML serializer.

You find one repo-relative path and SHA-256 over its exact bytes per primitive in
`face-surface.json`. `showcase/index.json` lists the HTML children in the same
sorted order. These are data instances and band membership, not private copies
of the `coronatio.face-surface.v1` schema; Caduceus owns that public seat.

## Source identity and repeatability

`source_sha` identifies the committed rendering-input snapshot, not the eventual
commit containing its own generated hash. For this initial generation it is
`6bf0972afcdcf2320c45abd4d4c690bea1919b87`. The generator compares the source
renderer and its included animation file, toast source, author-face bytes,
library CSS bytes, and ux CSS child membership with the named Git commit before
using it. Metadata-only artifact membership does not change that input snapshot.

On subsequent runs you retain the recorded pin while those inputs still match.
Otherwise the generator tries HEAD. You may select an exact matching committed
snapshot with `--source-sha <40-hex-commit>`. A dirty rendering input cannot be
truthfully attributed to an existing commit, so generation stops before replacing
artifacts until the input has a source commit. Keep that source commit reachable
when publishing the generated artifacts. This avoids an impossible self-referential
Git hash and allows a later artifact-only commit to regenerate without churn.
The generator's own implementation is versioned with the artifacts; `source_sha`
is the rendered crown input identity, not a hash of the generation tool.

`--check` recompiles the renderer and compares every generated byte. It reports
missing/different artifacts and stale HTML names without changing them. Ordinary
generation writes only changed artifacts. Stale files are reported, never silently
deleted. Unknown additive instance fields survive regeneration.

For the parent's HTTP comparison, take the Test fragment's original response
text (not a browser DOM serialization), select the same outermost `.ui-badge`
elements beneath `data-og-category-section="badges"`, and concatenate their exact
source ranges. Compare with `showcase/badge.html`. The parent owns release build,
HTTP evidence, schema-seat judgment, and publication; generation alone does not
close those boundaries.
